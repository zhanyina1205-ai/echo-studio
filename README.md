# 回声 · 工作室沟通与反馈台

独立的 React + TypeScript + Vite 手机 / 桌面网页。沿用奶油白、低饱和粉色、炭黑、圆角和手写批注的视觉语言。没有复制参考图的人物或照片，不修改「这一场」。

## 公开网页

- 小工具：https://zhanyina1205-ai.github.io/echo-studio/
- 产品提案：https://zhanyina1205-ai.github.io/echo-studio/proposal/
- 源码仓库：https://github.com/zhanyina1205-ai/echo-studio

手机可直接使用上面的HTTPS地址。本仓库和网页均公开，只包含代码、AI情境配图、虚构演示与虚构验收截图；没有真实演员、粉丝或工作室内部资料。你在网页录入的留言、口径、草稿与事件仍保存在当前浏览器，不会随GitHub提交上传。

原私有网址保持不变，和GitHub Pages不是同一来源；本地资料不会自动迁移。如需换入口，请在原站主动导出JSON，再在目标站选择JSON并预览合并。合并同ID保留目标站的当前项，不覆盖旧版本；导出的文件不加密，请自行保管。

同一GitHub Pages域名下的不同项目路径不是浏览器数据安全隔离区。「回声」使用独立数据库名；本提案代码不读取数据库，但同源页面在技术上并非权限隔离。

## 运行

需要 Node.js 22.12+ 或24。

```sh
git clone https://github.com/zhanyina1205-ai/echo-studio.git
cd echo-studio
npm ci
npm run dev
npm test
npm run build
npm run preview
```

开发端口5194，生产预览5195。生产输出在 `dist/`，可发布到 HTTPS 静态托管。

`npm test`同时运行工具与提案测试；`npm run build`同时构建工具，并把独立提案HTML放进`dist/proposal/index.html`。`npm run preview`可预览两个入口；开发服务器的`/proposal/`不是正式构建结果。

手机可打开最终 HTTPS 地址。局域网预览需要手机与电脑在同一网络、电脑保持服务运行、防火墙允许访问；本次不将桌面视口检查等同于真机或局域网验收。

## GitHub同步与发布

`.github/workflows/pages.yml`在推送`main`时执行锁定依赖安装、两部分测试与构建，再发布到GitHub Pages。拉取请求仅测试构建，不发布；支持手动运行。它发布的是程序，不会读取开发机或访客浏览器的IndexedDB。

提案源码与配图放在`proposal/`。工具页底部可以打开提案，提案中的工具入口均指向本仓库公开网页。修改本仓库后正常提交并推送即可更新公开版本；原独立私有项目不会被自动改写。

```sh
git add .
git diff --cached --stat
git commit -m "Update Echo app and proposal"
git push origin main
```

发布前检查暂存文件，勿提交真实资料或凭据。`.env*`、`qa/`、备份、构建产物、依赖与原私有托管身份配置默认不进入仓库。原始源码来源为独立工具提交`194c45d`与提案提交`8510c75`，公开发布工作区是单独副本，不自动双向同步。

## 第一版已实现

- 待处理：手工录入、批量粘贴、UTF-8 CSV 预览与字段映射、错误行提示、重复跳过或保留、搜索筛选、分类人工校正、状态维护。
- 规则分类：区分讨论对象、诉求、情绪、主题与核实信号。没有模型，没有粉丝个人画像或“黑粉 / 水军”身份判定。
- 回复台：口径来源、确认说明、适用事项、有效期与版本；只使用手工选定且有效的口径生成模板草稿。演示口径不能用于自己的留言。同事项同主题不同有效正文时保守阻止引用，不代表自动识别真实事实冲突。
- 草稿：手工改写、保存、待确认 / 需修改 / 本人确认；来源变更、过期、删除或停用提醒复查，阻止确认和复制。保留旧引用快照。修改已记录发布的原稿会另存新稿。
- 剪贴板：只有已确认且无未保存改写、无依据问题的草稿可以复制。复制不等于发布，失败有手动复制提示。平台发布结果仅由用户手填，没有接口发送或核验。
- 事件簿：关联多条留言，分开记录已确认与待核实，文字跟进人、状态、页面内到期提示、处理日志与原文入口。不是实际团队指派或后台通知。
- 反馈简报：按导入日期与演示 / 自己的资料筛选，保留混合、待确认情绪，原始条数与去重文本数分开。主题规则汇总能回到原文，人工备注、保存样本范围和 Markdown 导出。
- JSON 备份与非覆盖合并恢复；CSV 导出处理常见公式注入前缀；删除前确认；本地数据库事务与错误提示。

首次只有“虚构演示工作室”的10条留言、3条口径、1个事件。演示状态并非真实演员、工作室或粉丝资料；不是官方合作或背书。可以录入自己的资料，并使用“仅我的留言”范围排除演示。

## 数据边界

IndexedDB 数据库 `echo-studio-private-v1`，保存整个工作台的文字和关系。没有 localStorage 业务数据，没有业务上传、统计追踪、第三方字体、大模型调用或社交平台连接。

- 本版单个工作台的 JSON 数据上限4MB，单次文件导入5MB，每类主要记录最多5000项；没有大规模舆情处理能力。
- 备份使用紧凑 JSON，导入先校验结构、枚举、ID 与关联，再整笔事务写入。合并时同ID保留当前项，不覆盖工作台名称；不能用合并恢复去覆盖旧版本。
- 重复文本只统一首尾与连续空白，不剥离标点、表情或大小写，以免丢掉不同语气；重复不代表同一用户。
- 反馈简报保存所选留言ID和人工备注，不是不可变审计快照。原文和分类仍以当前记录为准。删除原文会解除简报、事件关联，但人工复制到摘要的文字需自行核对。
- 口径来源快照随草稿保留，删除口径不自动擦除旧草稿中的引用；界面会明确说明。
- 多标签保存使用版本检查拒绝旧页面覆盖，仍建议单页使用。没有跨设备同步或多人权限系统。
- 清理网站数据、更换网址、设备或浏览器可能导致丢失。本地不等于云备份或加密；JSON / CSV / Markdown 导出文件也不加密。
- 已发布程序代码不包含当前浏览器的工作台资料。本地预览与托管网址不是同一来源，资料不会自动迁移。
